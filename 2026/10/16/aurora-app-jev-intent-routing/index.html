从传统 LLM 到 Jev：更快的意图识别与路由分发

AI 收到用户消息后，通常要先判断用户想做什么，再把任务交给对应流程。

传统做法是让 LLM 生成分类 JSON。Jev 的做法更直接：不生成文字，只返回选择和概率。

LLM 分类

程序只需要一个意图，却要等待模型生成 JSON，再处理解析失败、字段错误和非法选项。

二、Jev 是什么，能做什么

Jev 是专门做判断的模型，可以理解成一个“智能 if”。

能力 回答什么 示例
Choice 选哪个 用户属于哪种意图
Score 程度有多高 请求风险是低、中还是高
Noul 是不是 是否继续上一个任务

Jev 和传统 LLM 的差异

对比项 传统 LLM Jev
擅长 生成、解释、推理 分类、路由、评分
输出 文本或 JSON 选择、分数、概率
答案范围 可能超出候选 只能从候选中选择
多个判断 常需多次调用 一次请求并行完成

四、Jev 的优势：速度、代码和费用

1. 速度更快

对比项 传统 LLM Jev
输出方式 逐 token 生成 直接返回决定
多问题判断 常需多次调用 一次并行完成
文章中的延迟 约 3～329 秒 约 70～500ms
官方最高值 对照基线 特定测试中快 193.6 倍

实际应用中，可以期待意图判断从秒级缩短到亚秒级。193.6 倍是官方特定测试的最高值，不是固定结果。

2. 代码更简单

处理步骤 传统 LLM Jev
生成分类文本 需要 不需要
截取 JSON 可能需要 不需要
JSON.parse 需要 不需要
校验非法枚举 需要 Choice 已限制候选
并行判断多个问题 编排复杂 一次请求完成

Jev 不能删除所有代码。网络错误、超时、阈值和降级处理仍然需要保留，但文本解析代码会明显减少。

3. 调用费用更低

对比项 传统 LLM Jev 文章中的数据
输入费用 取决于所选模型 约 $0.042/百万 token
输出费用 通常按 token 收费 免费
多个判断 可能多次付费 一次请求并行完成
官方最高值 对照基线 特定测试中便宜 444.6 倍

每次输入 1,000 token 时：

这只计算 Jev 的输入费用，不包括网关、日志和 LLM 兜底费用。444.6 倍同样是官方测试中的最高值。

最后看一张总表

维度 传统 LLM Jev
速度 通常为秒级 文章数据为 70～500ms
代码 需要生成、解析和校验 直接使用类型化决定
费用 输入、输出都可能收费 输入便宜，输出免费
准确率 复杂理解通常更强 不保证高于 LLM
最佳用途 推理、解释、内容生成 意图识别、路由、评分

Jev 的价值不是全面替代 LLM，而是让选择题不再经过文本生成：

代码处理确定规则，Jev 处理高频选择，LLM 处理复杂问题，人处理高风险决定。
