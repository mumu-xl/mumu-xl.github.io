从零搭建前端 CI/CD 流水线：GitLab + Docker 实战指南

前言

在传统的前端开发流程中，我们通常需要手动执行 npm run build，然后通过 FTP 或 Scp 将构建产物上传到服务器。这种方式不仅效率低下，还容易出错。

本文将带你从零开始，在自建 GitLab 服务器上配置一套完整的前端 CI/CD 流水线，实现代码推送 → 自动构建 → Docker 镜像打包 → 自动部署的全流程自动化。

最终效果：当你执行 git push origin main 后，只需等待几分钟，刷新浏览器就能看到最新的页面。

一、整体架构

flowchart LR
    A[开发者推送代码] --> B[GitLab 触发流水线]
    B --> C[GitLab Runner 拉取代码]
    C --> D[安装依赖 & 构建项目]
    D --> E[生成 dist/ 产物]
    E --> F[Docker 构建镜像]
    F --> G[停止旧容器 & 启动新容器]
    G --> H[部署完成 ✅]

八、常见问题与解决方案

问题 原因 解决方案
docker: not found deploy-job 未使用 Docker 镜像 添加 image: docker:latest
Cannot connect to Docker daemon 未挂载 Docker 套接字 添加 -v /var/run/docker.sock:/var/run/docker.sock
host not found in upstream "app" Nginx 配置引用了不存在的后端服务 删除或修正 upstream 配置
流水线卡在 Pending Runner 未在线或 tag 不匹配 检查 Runner 状态和 .gitlab-ci.yml 中的 tags
Dockerfile: no such file or directory Dockerfile 未提交到仓库 提交 Dockerfile 到项目根目录
